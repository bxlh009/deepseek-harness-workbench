# 设置分区导航服务

[English](2026-08-15-settings-section-navigation-service.md) | 中文

## 问题

侧栏把拉取请求、站点、已安排和插件显示为产品导航，但此前它们全是不可交互的占位项。插件已经有真实设置页面，继续显示为死入口会让已实现功能无法访问，也会让尚未实现的产品看起来像坏掉了。

## 决策

`ui-settings` 现在提供 `ctx.settingsNavigation`。这是一个小型 Cordis 服务，把稳定的分区 id 路由到当前挂载的设置外壳。设置外壳在 React 生命周期中挂接组件本地的 `openSection` 回调，侧栏依赖该服务打开真实的 `plugins` 分区。

只渲染已经实现的目的地。拉取请求、站点和已安排在其所属服务与产品页面真正存在之前不会显示。这样既避免虚假入口，也不需要制造空页面。

## 边界

展示包不会导入其他插件的运行时值。Context 形状通过仅类型的客户端导入获得，运行时协作使用 Cordis；设置外壳仍是弹窗和当前分区状态的唯一所有者。没有采用 DOM 自定义事件，因为它会隐藏依赖顺序，而且在设置外壳不存在时无法清晰失败。

## 验证

- 导航服务的路由、替换与释放单元测试。
- 通过挂接点打开插件分区的设置外壳测试。
- 证明插件为真实按钮且未实现入口不出现的侧栏测试。
