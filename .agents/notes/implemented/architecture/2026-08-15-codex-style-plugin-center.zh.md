# Codex 风格插件中心：第一阶段

[English](2026-08-15-codex-style-plugin-center.md) | 中文

## 背景

插件设置过去只显示配置表单和平铺的 Loader 清单，缺少桌面编码智能体应有的导航和目录体验。OpenAI 的插件模式把发现、安装与已安装插件提供的能力分开处理。

DeepSeek Harness 目前还没有应用级插件目录或事务式安装 API。现有 Host remote 只是当前 Cordis Loader 条目的只读投影。在这个接口上直接放置“安装”按钮会制造不存在的能力。

## 决策

第一版插件中心提供两个真实视图：

- “配置”显示可配置本地插件贡献的设置。
- “已安装”显示当前 Host Loader 清单，支持搜索、启用状态筛选、状态统计、模块标识和可展开的运行时详情。

后续管理能力不会把 Loader 清单伪装成下载市场。可选条目提供无障碍开关，由仅监听回环地址的 `pluginInventory/setEnabled` Remote 支持。Host 持久化直接禁用标记，并在 Cordis 应用更改后返回新快照。

运行主干条目不可切换，避免连接、设置、Shell 和清单功能关闭自己的管理路径。Typert Loader 与注册表同样属于主干；禁用任一项都会移除暴露 Loader 能力的桥梁。因此受保护卡片会明确标注核心组件，并显示禁用的开关，而不是发起 Host 必须拒绝的变更。

卡片加入本地化能力分类说明，同时在详情中保留精确的模块说明符和 Loader id。搜索和筛选使用原生控件，具备可见焦点和按下状态语义；工具栏在窄设置面板中改为纵向排列。

## 后续边界

Codex 风格的浏览和安装需要独立的可信目录服务，以及用于包安装、卸载、进度、权限披露、重启/重载和回滚的 Host 操作。现有 CLI `dsh plugin` 命令可以作为安装机制，但不得直接从浏览器渲染进程调用，也不能把它描述成已经完成的桌面工作流。
