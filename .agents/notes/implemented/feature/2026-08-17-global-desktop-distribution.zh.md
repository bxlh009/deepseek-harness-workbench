# Agent Note: 全球桌面分发

Status: implemented

[English](2026-08-17-global-desktop-distribution.md) | 中文

## Problem

桌面包面向中文环境之外的用户，但最终回退到中文、仅有中文的原生更新提示以及地区化品牌会让全新安装难以理解。通过并发发布请求上传安装包元数据还可能把同一版本拆成多个 GitHub Release，而开放仓库也需要在变更成为可下载二进制文件前自动检查凭据。

## Decision

当已存偏好和浏览器请求的语言都不属于已发布语言时，英语作为最终回退语言。中文浏览器变体仍选择中文，可见的语言设置继续保留明确的 `zh` 与 `en` 选择。缺失翻译回退到英语，避免全球用户仅因字典缺项而收到无关的中文片段。

桌面包、启动页、安装元数据、PWA 元数据和英文侧边栏统一使用稳定名称 `DeepSeek Harness Workbench`，并采用本地优先编码代理描述。Electron 更新弹窗只在应用 locale 为 `zh` 时选择中文，其他 locale 均使用英语。

桌面发布自动化在关闭发布功能的情况下构建 NSIS 安装包，验证安装包、blockmap 和 `latest.yml`，然后为该版本创建或更新唯一的普通 GitHub Release。仓库在 push 和 pull request 时通过 Gitleaks 扫描完整历史；只有两个精确匹配的非生产测试凭据进入白名单。

## Alternatives considered

**继续把中文作为通用回退语言。** 这能保留原有产品侧重，但会让不受支持的浏览器语言意外显示中文，与全球分发目标冲突。

**为每种语言分别命名产品。** 本地化产品名会削弱更新、安装程序、快捷方式和支持场景中的身份一致性。稳定的英文产品名配合本地化描述更容易查找和诊断。

**让 Electron Builder 直接发布资产。** 当资产上传发生竞争时，其发布器可能创建相互竞争的草稿 Release。先构建，再通过单个 GitHub CLI 步骤发布经过验证的产物集合，可以让每个版本只有一个 Release 所有者。

**忽略所有测试目录的凭据扫描。** 这会隐藏误粘贴进测试代码的真实凭据。仅将精确的测试值加入白名单，仍会扫描其他所有测试值。

## Consequences

全新的非中文安装会以英语打开，中文仍是一等可选界面。GitHub、Windows、PWA 元数据和更新提示使用一致的产品身份。缺少任一更新产物时发布任务失败，发现密钥会阻止仓库检查。尚未接入 locale 注册表的局部内联文案仍由对应包继续处理。
